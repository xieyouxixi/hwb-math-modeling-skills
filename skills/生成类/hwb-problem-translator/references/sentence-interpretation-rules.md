# 逐句解释规则

## 一、为什么要逐句

研赛题干由命题人按"工程背景 → 问题提出 → 任务要求 → 数据说明"四段写成，中间夹带大量**限定词**。这些限定词决定了模型的边界条件，也是评委判断"你是否真的读懂了"的直接依据。逐句解释的目的不是复述，而是**把限定词转成可执行的约束**。

## 二、句子切分

- 以**句号、分号、编号（1）（2）**为边界切分；
- 长句内的**条件从句单独成单元**（"在……条件下""若……则……""除……外"）；
- 每个单元分配稳定 ID（`S01`…），后续所有引用都用 ID，便于回溯与审计。

## 三、五问法

对每个句子单元依次回答：

| 问 | 内容 |
|---|---|
| ① 在说什么 | 白话复述，禁止照抄原句 |
| ② 是什么类型 | 定义 / 约束 / 数据口径 / 交付要求 / 背景 / 修辞 |
| ③ 限定词是什么 | 时间、范围、单位、精度、适用条件 |
| ④ 隐含了什么 | 未明说的物理或业务限制 |
| ⑤ 如果我理解错会怎样 | 对后续模型的影响 |

第 ⑤ 问是关键：**只写"理解错会出问题"是无效的**，必须写清影响哪一问、导致什么后果。

## 四、限定词高危清单

| 限定词 | 常见陷阱 |
|---|---|
| "仅考虑……" | 排除项被忽略，导致模型过度复杂 |
| "假设……不变" | 把假设当事实，未做假设合理性检验 |
| "至少 / 不超过 / 不低于" | 边界条件，往往是不等式约束 |
| "在……范围内" | 数据截断，外推会失效 |
| "平均 / 总体 / 逐日" | 统计口径，决定聚合层级 |
| "忽略……" | 简化条件，需要在模型假设中呼应 |
| "基于附件 N" | 数据来源绑定，用错附件=跑题 |
| "给出……并说明理由" | 交付物含**论证**而非只有数值 |

## 五、交付物还原

把每处"请给出/请建立/请分析/请评价"翻译成具体交付物形态：

| 动词 | 交付物 | 常见形式 |
|---|---|---|
| 建立 | 模型 | 公式体系 + 变量说明 + 求解方法 |
| 求解 | 数值结果 | 结果表 / 图形 / 最优方案 |
| 分析 | 归因或敏感性 | 敏感性表、因素排序、讨论 |
| 评价 | 指标体系结论 | 指标表 + 权重 + 排序 |
| 预测 | 外推结果 | 预测值 + 区间 + 误差指标 |
| 给出方案 | 决策方案 | 可执行方案表 + 理由 |

漏掉"并说明理由"这类附属要求，是研赛最隐蔽的失分点。

## 六、跨问题依赖的处理

研赛的 3–5 问通常构成一条链：**前面的结果成为后面的输入**。翻译时必须显式标注：

- **数据依赖**：问 2 用了问 1 清洗后的数据 → 问 1 的数据处理错误会级联；
- **模型依赖**：问 3 复用问 2 的参数 → 参数必须做不确定性传播；
- **结论依赖**：问 4 的评价基于问 3 的预测 → 预测误差要传到评价结论上；
- **反向依赖**：问 5 要求"若问 2 条件变化则重新讨论" → 要做情景分析。

依赖图用 Mermaid 输出，节点为问题编号，边标注传递的内容（数据/参数/结论）。

## 七、待澄清清单

遇到下列情况必须写入待澄清清单，**不得擅自假设后不声明**：

1. 附件缺失或附件说明与数据不一致；
2. 单位缺失或前后不一致；
3. 同一术语在不同问中含义不同；
4. 任务要求与数据能力不匹配（例如要求精度但数据分辨率不足）；
5. 存在多种合理解读且分支影响显著。

每条要给出**若按 A 理解 / 若按 B 理解**的分支影响，以及**建议采用哪种并在模型假设中声明**。研赛允许在论文中做合理假设，但假设必须写出来、且要说明为什么合理。
