# 研赛评审关注点信号（命题人视角）

翻译赛题时要同时回答一个元问题：**命题人希望评委在论文里看到什么？** 研赛采用"网上评审 + 集中评审"两轮，网评阶段评委在极短时间内读摘要与结构，集中评审才细看模型。以下信号按这一流程归纳。

## 一、网评阶段的"三秒判据"

评委在网评时最先看到的顺序是：**首页封皮 → 摘要页 → 问题重述与问题分析的小标题**。因此：

| 位置 | 命题人期望看到的 | 反向信号（危险） |
|---|---|---|
| 摘要 | 建模思路、主要方法、模型、结果与结论、创新点**五要素齐备** | 只写背景与意义，没有具体结果数字 |
| 摘要 | 出现**具体数值结论**（如最优值、精度、提升幅度） | 通篇"进行了研究""建立了模型" |
| 小标题 | 能一眼看出"每一问用什么方法" | 标题都是"模型的建立与求解" |
| 摘要页 | **不超过两页** | 摘要写到第三页（违反格式规范） |

## 二、集中评审的"完整性判据"

研赛与本科国赛最大的差别在于**验证要求更高**。评委在集中评审时按下列维度找证据：

| 维度 | 命题人期望的证据 | 常见缺失 |
|---|---|---|
| 模型建立 | 从机理或数据出发的**推导过程**，而非直接给公式 | 公式来源不明，变量突然出现 |
| 模型求解 | 算法选择有理由，规模适应性有说明 | 只说"用 Python 求解" |
| 结果检验 | **独立**的验证（留出集、交叉验证、物理合理性、对比基线） | 用训练误差当验证结果 |
| 灵敏度分析 | 关键参数扰动对结论的影响，**给出结论的稳健性边界** | 只给一张图不解读 |
| 误差分析 | 误差来源分类（数据/模型/数值） | 直接把误差归给"数据噪声" |
| 创新点 | 有对照基线，说明改进量与代价 | 自称创新但无对比 |

## 三、按题型族的评审侧重

| 题型族 | 评委最先看 | 最容易被扣分 |
|---|---|---|
| 信号与通信 | 噪声/干扰模型的合理性、估计精度 | 忽略干扰模型，直接套现成算法 |
| 优化与调度 | 约束完整性、可行性与最优性 | 约束漏写，解不可复现 |
| 数据驱动与预测 | 划分方式、泛化能力、机理耦合 | 过拟合、只用一层数据切分 |
| 医学与生物 | 结果的可解释性与合理性讨论 | 纯黑箱，无临床/生物讨论 |
| 能源、双碳与地理 | 指标体系与情景设定 | 权重无依据 |
| 评价与美学量化 | 指标可操作化、信效度 | 主观指标硬凑数字 |
| 力学与守恒 | 守恒关系是否显式、量纲是否自洽 | 量纲不一致 |

## 四、研赛特色加分项

| 加分点 | 说明 |
|---|---|
| **华为赛题的工程落地性** | 华为题常来自真实工程问题，论文若给出可落地的工程建议（含代价评估）会明显加分 |
| **"数模之星"所需的展示性** | 每题前 2 队可进答辩，因此**结果的可视化与可复现性**在集中评审阶段被看重 |
| **代码与附件质量** | 附件可选（≤50MB），但若上传，程序的可读性与可复现性会被查看；论文中须注明已上传附件 |
| **匿名合规** | 除首页外不出现单位/姓名/队伍编号。这是**有效性**问题，不是风格问题 |
| **AI 使用披露** | 研赛允许 AI 作为辅助工具但须注明来源，如实披露反而体现规范意识 |

## 五、翻译阶段的自我检查

对照以下问题自检翻译质量：

1. 我能否说出这道题**评委一定会看的那三个点**？
2. 题目里有没有一句话是我读了三遍还是不确定的？→ 必须进待澄清清单。
3. 这道题有没有"看起来很花哨但其实是干扰项"的部分？→ 标注为修辞类。
4. 这道题最可能被"做偏"的地方在哪？→ 在风险提示中前置说明。
5. 如果我是命题人，我会觉得哪一问最有区分度？→ 标记为关键问，后续建模优先投入。

## 六、边界声明

本文件归纳的是**评审关注倾向**，不是官方评阅细则。研赛官方不公布逐年评分表；《竞赛通知》只明确**奖项比例上限（一等 ≤1.5%、二等 ≤13%、三等 ≤20%）**与违规判定标准。凡涉及具体分值的内容，一律以当年专家委员会口径为准，不得在论文中引用本文件的倾向性描述作为评分依据。
