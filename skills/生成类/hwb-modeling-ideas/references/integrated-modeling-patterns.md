# 跨问整合与多模型耦合模式

研赛一题通常 3–5 问，且问题之间存在真实的依赖。本文件给出把多问整合为**一条主线**的常见模式与耦合时的注意事项。

## 一、为什么必须整合

| 不整合的后果 | 整合的收益 |
|---|---|
| 每问换一套模型 → 论文像五篇小论文拼接 | 主线模型贯穿 → 评委看到"体系" |
| 符号体系反复重定义 → 符号说明混乱 | 符号一次定义全文复用 |
| 前一问结果无法支撑后一问 → 逻辑断裂 | 数据/参数/结论显式传递 |
| 缺少全局结论 → 摘要写不出结论 | 摘要能给出体系性结论 |

## 二、五种整合模式

### 模式 1：链式（预测 → 决策 → 评价）

```text
问1 数据/机理建模 → 问2 预测 → 问3 基于预测的优化 → 问4 方案评价
```

**要点**：问 2 的预测误差必须在问 3、4 中传播。做法是把点预测换成**区间预测**或做**蒙特卡洛情景**，否则评委会问"你的最优方案对预测误差多敏感"。

### 模式 2：并联 + 融合

```text
问1 方法A → 结果A ┐
问2 方法B → 结果B ├→ 问3 融合/对比 → 结论
```

**要点**：融合需要**准则**（误差最小？稳健性最好？），不能"取平均了事"。

### 模式 3：机理定结构 + 数据定参数

```text
问1 机理推导结构 → 问2 用数据辨识参数 → 问3 用参数化模型做决策
```

**要点**：参数辨识要给**置信区间**，并说明可辨识性（是否唯一）。

### 模式 4：逐层细化

```text
问1 宏观总量 → 问2 中观分配 → 问3 微观排程
```

**要点**：上下层之间的**一致性约束**必须显式（下层之和 = 上层总量）。

### 模式 5：情景驱动

```text
问1 现状建模 → 问2 设定情景 → 问3 各情景求解 → 问4 情景对比与推荐
```

**要点**：情景设定要有依据（政策目标、参数区间），并给出**推荐方案的适用边界**。

## 三、耦合时的四个陷阱

| 陷阱 | 表现 | 规避方法 |
|---|---|---|
| 误差不传播 | 用点预测的最优解，忽略预测误差 | 区间预测 / 鲁棒优化 / 情景分析 |
| 量纲不统一 | 上下层单位不一致，聚合出荒谬数值 | 建立统一量纲表，聚合前换算 |
| 口径漂移 | 同名指标在不同问中定义不同 | 定义表全文唯一，改动需全局回溯 |
| 循环依赖 | 问 3 需要问 4 的结论 | 拆成迭代求解，说明收敛条件与迭代次数 |

## 四、整合后的自检

1. **主线可陈述性**：能否用一句话说清全文主线？说不清说明未整合。
2. **依赖可追溯**：每问的输入是否都能指向前一问的具体产出？
3. **符号唯一性**：全文符号是否只定义一次？
4. **误差传播可见**：若前问有误差，后问结论是否标注了稳健性？
5. **结论层次**：是否既有分问结论、又有全局结论？
6. **四天可完成**：整合方案的总工作量是否还在四天赛程内？

## 五、反面清单（不要这么做）

- 为了"显得丰富"在每问都引入新模型 → 主线消失；
- 把前一问的结果直接当精确值使用，不做敏感性 → 结论不可靠；
- 用不同软件、不同符号体系分别求解各问 → 复现性差；
- 只在最后一段写"综上"，前面各问毫无关联 → 整合失败；
- 把所有问都做成"评价题"以规避建模难度 → 明显的降维应试，评委会识别。
