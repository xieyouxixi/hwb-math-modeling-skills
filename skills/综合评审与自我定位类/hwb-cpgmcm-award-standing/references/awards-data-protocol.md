# 华为杯培养单位获奖数据协议（awards-data-protocol）

本文件规定 `hwb-cpgmcm-award-standing` 技能所用数据的来源、填写规范、字段定义、更新流程与禁止编造红线。所有涉及单位获奖数据的表述必须以本文件为准。

## 一、赛事口径（研究生赛，无赛区/无省奖/无组别）

“华为杯”中国研究生数学建模竞赛（CPGMCM）为研究生层次全国统一评奖赛事：

- **不设赛区**、不设本科组/高职高专组，也没有“省奖/国奖”双层模型；
- 全国统一评奖：一等奖、二等奖、三等奖，以及华为专项奖、“数模之星”冠亚季军与提名奖、成功参赛奖、优秀组织单位等；
- 竞争校准维度为：**赛题（A—F 六题）难度 + 参赛培养单位 + 是否选择华为赛题**；
- 2025（第二十二届）实际比例：一等 244 队（1.00%）、二等 3085 队（12.66%）、三等 4830 队（19.82%），总获奖率 33.48%。

本技能不依赖任何未被核实的单位获奖数据。

## 二、数据来源

仅接受以下两类已公开、可核实来源：

1. **官方获奖名单公告**：中国研究生创新实践系列大赛管理平台 <https://cpipc.acge.org.cn/> 发布的当届获奖名单；
2. **各培养单位公开获奖通报**：培养单位官网、研究生院/学院新闻稿中明示的本单位获奖情况。

以下信息**本仓库不提供、也不伪造**：

- 当届官方《论文格式规范》《论文模板》《操作手册》（须从官方平台获取）；
- 任何未公开、未逐条核对的单位获奖明细；
- 指导教师高频度、队伍成员姓名等可能泄露身份信息的数据。

## 三、文件与字段定义

### assets/cpgmcm_annual_statistics.csv（历年总量统计）

| 字段 | 含义 | 口径 |
|---|---|---|
| 年份 / 届次 | 赛事年份与届次 | 2020=第十七届 … 2025=第二十二届 |
| 参赛培养单位数 / 参赛队伍数 | 当届总量 | 仅填已公开核实值 |
| 一等奖队数 / 一等奖比例 | 全国一等奖数量与占比 | 比例 = 一等队数 / 参赛队伍数 |
| 二等奖队数 / 二等奖比例 | 全国二等奖数量与占比 | 同上 |
| 三等奖队数 / 三等奖比例 | 全国三等奖数量与占比 | 同上 |
| 总获奖队数 / 总获奖率 | 一+二+三合计与占比 | 同上 |
| 数据来源 | 取值出处说明 | 官方公告 / 待核对官方公告 |

已核实写入：2024（521 单位 / 20247 队）、2025（631 单位 / 24371 队，分项比例见上）。其余年份字段留 `NA` 或留空。

### assets/unit_awards_template.csv（培养单位记录模板，空白）

| 字段 | 含义 |
|---|---|
| 培养单位名称 | 官方全称，便于模糊查询 |
| 2024_一等奖 / 2024_二等奖 / 2024_三等奖 | 该单位 2024 年各等奖项数（或 NA） |
| 2025_一等奖 / 2025_二等奖 / 2025_三等奖 | 该单位 2025 年各等奖项数（或 NA） |
| 华为专项奖_命中次数 | 该单位在华为专项奖累计命中次数（或 NA） |
| 数据说明 | 来源标注（官方公告 / 单位通报 / 待核对） |

该文件**初始为空模板**（仅表头 + `#` 注释）。使用者须自行从官方名单填入；未填写时脚本走“数据未填写”分支。

## 四、填写规范

1. 每行代表一个培养单位；单位名称尽量使用官方全称，避免简称歧义。
2. 数值仅填已从来源逐条核对的内容；无法确认的写 `NA` 或留空，**禁止编造**。
3. 比例字段保留两位小数为宜，形如 `1.00%`；与总量 CSV 口径保持一致。
4. 新增年份列时须同步更新表头，并与 `cpgmcm_annual_statistics.csv` 的年份/届次对应。
5. `#` 开头的行为注释，脚本读取时跳过，不得删除其填写说明。

## 五、更新流程

1. 当届赛事结束后，从官方平台导出获奖名单；
2. 对总量 CSV 补入当届参赛单位数、队伍数、各等奖数量与比例，更新“数据来源”列；
3. 对单位模板，按官方名单逐单位补入各等奖项数；无法逐条核对的单位保持 `NA`；
4. 更新 `references/awards-data-protocol.md` 的“已核实”说明与 SKILL.md 中的比例引用；
5. 保留历史年份字段，已过期但已核实的数据继续保留，未核实字段维持 `NA`。

## 六、禁止编造红线

- **不得凭印象、传闻或“应该差不多”填写任何未核对的单位获奖数据**；
- **不得用总量数据反推或插值出某单位的具体获奖数**；
- **不得为“看起来完整”而把 NA 填成 0 或估计值**（0 表示确知为零，估计值须标 NA）；
- 模板未填写时，技能只能输出**方法性建议**与全国基线先验，**不得虚构单位历史记录**；
- 任何概率/区间预测必须标注为**经验估计**，并声明非官方、不构成获奖承诺；
- 不得因某单位无历史获奖而断定其学生不能获奖；数据仅作先验，须给出不确定性。

## 七、查询脚本边界

`scripts/query_unit.py` 仅读取 CSV，不联网、不缓存外部数据。模板为空时返回 `data_not_filled`，给出方法性建议而非崩溃。脚本所有定位建议均以 1.00% / 12.66% / 19.82% 基线为锚点，并标注“经验估计”。
