# 问题重述撰写规则

## 一、定位

问题重述是论文的第一章。它回答"**题目要我做什么**"，不回答"我打算怎么做"（那是问题分析）、"我做了什么"（那是模型建立与求解）。

研赛中重述的作用被放大：网评阶段评委先看摘要，紧接就扫一眼重述与问题分析的小标题，判断这篇论文**有没有读懂题**。重述写得散，后面模型再好也容易被低看。

## 二、三段式结构

### 2.1 研究背景

- 篇幅 1—3 段，**只写与任务直接相关的背景**；
- 研赛题目多源自工程技术与管理科学实际问题（芯片、通信、能源、医学、气象、交通等），背景段要落回**工程场景**，不要写成百科式科普；
- 末尾用一两句过渡到"本文将针对上述问题建立数学模型"。

**禁止**：大段行业综述、政策罗列、与本任务无关的技术史。

### 2.2 问题回顾

- 逐问独立成段，编号（1）（2）（3）……；
- 每问包含三要素：**已知什么（数据/条件）→ 要求做什么（任务）→ 交付什么（形式）**；
- 保留关键数字与单位（样本量、时间范围、精度要求）；
- 语义等价，措辞不重复原题。

**高频错误**：把多问合并成一段；漏掉"并说明理由""并给出评价指标"这类附属要求。

### 2.3 研究综述

- 400—600 字；
- 按**方法族**组织，而非按文献罗列；
- 结构建议：该问题的主流方法方向 → 各方向的适用条件 → 现有限制 → 本文切入点（1—2 句，不得剧透具体模型结果）。

## 三、重述的语言规范

| 要求 | 说明 |
|---|---|
| 人称 | 第三人称，避免"我们认为" |
| 时态 | 任务描述用现在时；背景可用完成时 |
| 术语 | 与题目完全一致，不自造近义词（例：题目叫"相关矩阵组"就不能写成"相关矩阵集合"） |
| 单位 | 与题目一致，不擅自换算 |
| 符号 | 重述阶段尽量不用公式；若必须用，采用题目原始符号 |

## 四、边界（最容易越界的地方）

| 不要写 | 为什么 |
|---|---|
| "本文采用 XX 模型" | 属问题分析 |
| "由于数据存在缺失，采用插值处理" | 属数据预处理 |
| "目标函数为……" | 属模型建立 |
| "求解得最优值为……" | 属结果 |
| "该方法精度可达 95%" | 属结果 |
| "本文的创新点在于……" | 属模型总结 |

重述里出现上述任何一句，都算**章节越界**，自查模式下按"重要问题"报。

## 五、研赛特别提示

1. **补充说明优先**：研赛常在赛题 ZIP 中附带"补充说明""更正说明"。若补充说明修改了数据口径或任务要求，重述必须采用**最新口径**，并在"待核对事项"中记录这一变更。
2. **附件要点名**：研赛附件多（曾有题目附上百个数据文件），重述要说明各附件在任务中的作用，而不是只说"附件提供了数据"。
3. **华为题标注**：若为华为赛题，可在背景中点出工程背景属性，但不要写成"为获得华为专项奖"这类功利表述。
4. **页数控制**：重述 + 问题分析合计不要挤占模型章节篇幅。研赛正文篇幅有限，重述通常 1—2 页。
5. **匿名合规**：重述中**不得**出现培养单位、姓名、队伍编号（研赛规定除首页封皮外一律禁止）。
