# HWB Problem Restatement

按用户请求在两种模式下工作：

- **生成模式**：用户给出完整赛题，要求写成问题重述章节；
- **自查模式**：用户同时给出完整赛题与已写好的问题重述章节，要求诊断。

不要把**问题回顾**与独立的**问题分析**章节混淆。问题重述只说明"题目要我做什么"，不选模型、不分析变量关系、不描述算法、不报告结果。

在读 [references/restatement-rules.md](references/restatement-rules.md) 之后开始任一模式。自查模式还要读 [references/review-checklist.md](references/review-checklist.md)。

## 生成模式

以完整赛题为事实来源。保留每一项实质性任务、数字、单位、时间范围、样本量、约束、附件作用与要求的输出形式。**重述而非同义词替换**。

输出：

```markdown
# 1 问题重述

## 1.1 研究背景

【1—3 段，与任务直接相关；研赛题目多来自工程技术与管理科学实际问题，背景段落须点出工程场景】

## 1.2 问题回顾

根据题目提供的数据、条件和任务要求，需要解决以下问题：

（1）【问题一的独立表述】

（2）【继续覆盖全部问题，研赛通常 3—5 问】

## 1.3 研究综述

【总体研究现状、主要方法方向、适用任务、局限与本文可能切入点】

## 待核对事项

- 【歧义、缺少的附件说明或待核验文献；无则写"无"】
```

### 研究综述的证据要求

- 绝不虚构作者、论文、期刊、年份、结论或 URL。
- 用户提供了已核实文献时，只使用这些来源，除非用户授权另行检索。
- 具备联网条件且用户要求引用文献时，检索真实的一手或权威来源并引用。
- 没有已核实文献时，写**方法层面**的综述，不编造引用，并显式标注 `具体文献需要补充并核验`。不要让"看起来像引用"的占位符显得真实。

生成的章节通常控制在 **1—2 页**，其中研究综述约 400—600 字，除非竞赛另有规定。

## 自查模式

把草稿与原始赛题对照。除用户明确要求外，只诊断不重写。

按以下顺序输出：

1. **审查结论** — 2—4 句，说明完整性与最高风险；
2. **问题清单** — Markdown 表：`等级 | 位置/原文 | 类型 | 说明 | 评阅影响 | 修改建议`；
3. **题意保持核对** — 任务、条件、数字、单位、约束、附件、输出形式；
4. **章节边界核对** — 模型、算法、分析、公式或结果是否越界写进了重述；
5. **研究综述核对** — 相关性、均衡性、证据与虚构引用风险；
6. **修改优先级** — 三个最高价值的动作；
7. **待核对事项** — 仅凭现有材料无法确认的条目。

等级使用 `严重问题 / 重要问题 / 一般问题 / 优化建议`。每个严重或重要问题都要给出位置与具体证据。某一等级没有问题就不要凑。

## 研赛专属核对项

| 项 | 要求 |
|---|---|
| 问题数量 | 研赛常见 3—5 问，逐问必须独立成段，不得合并 |
| 补充说明 | 研赛赛题常有"补充说明""更正说明"，其口径**优先于主赛题**，重述必须反映最新口径 |
| 附件说明 | 附件的作用要在重述中点到（"基于附件 N 提供的……数据"） |
| 命题方 | 若为华为赛题，可在背景中点出工程背景属性，但**不得**写成"因为要拿华为专项奖所以……" |
| 页数 | 重述通常压在 1—2 页，为后续模型章节留出篇幅 |

## Shared safeguards

- 不要为了降低文字重复率而改变题意。
- 原题不完整或附件缺失时，保留确定部分并列出缺口；不要猜测。
- 文献综述是题目要求的格式组成部分，不构成虚构外部事实的许可。
- 使用客观的第三人称学术中文。
- 用户说"检查"或"点评"时，先诊断；只有明确要求时才给改写稿。
- 竞赛进行中提醒用户：**不得就赛题内容与队外任何人讨论**。
