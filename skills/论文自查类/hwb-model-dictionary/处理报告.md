# 词典构建说明（处理报告）

本文件记录 `assets/model-dictionary.json` 的构建过程、数据结构、条目统计与使用方式。

## 一、构建方式

`assets/model-dictionary.json` 由 [`scripts/build_dictionary.py`](scripts/build_dictionary.py) **确定性生成**（不含时间戳，可重复运行得到同一份资产）：

```bash
python scripts/build_dictionary.py
python scripts/build_dictionary.py --out assets/model-dictionary.json   # 等价
```

构建原则：

1. **面向研赛题型族**，而非通用方法论百科。每条档案都写清它服务于哪类赛题（`适用场景` 中的题号信号 + `适用题号` 检索字段）。
2. **数据要求可操作**：写出该模型需要什么形态的输入，使「数据够不够」成为可判定的问题。
3. **禁忌点与缺陷具体化**：写明模型在什么条件下会给出错误结论，而非笼统的「精度可能不足」。
4. **检验路线独立**：每条都给出至少一种独立验证方式，避免「用训练误差自证」。
5. **成本受赛程约束**：赛程为 **4 天**（约 100 小时），因此所有条目的隐含实现成本上限是「四天内可完成」。

## 二、数据来源

- 题型与真题对照：本地收录的 **2020—2025 年 36 道真题**（见 [`数模资料/历年赛题库/赛题库总览.csv`](../../../数模资料/历年赛题库/赛题库总览.csv)）；
- 方法学口径：通用建模范式与各方法的标准适用条件、失效条件与检验方法；
- 赛事约束：赛程 4 天、论文格式与匿名硬约束、附件 ≤50 MB（详见 [`数模资料/官方文件/华为杯赛事事实基准.md`](../../../数模资料/官方文件/华为杯赛事事实基准.md)）。

## 四、字段说明

根节点字段：

| 字段 | 含义 |
|---|---|
| `数据集名称` | 资产名称 |
| `制作方` | 生成方标识 |
| `使用许可` | 使用范围与引用要求 |
| `版权与传播声明` | 版权、传播限制，以及「适用题号」的口径声明 |
| `数据` | 模型条目数组 |

条目字段（`数据[]`）：

| 字段 | 含义 |
|---|---|
| `序号` | 条目序号（1 起，与生成顺序一致） |
| `模型名称` | 方法中文名 |
| `模型大类` | 一级分类（9 类，见上表） |
| `具体分组` | 二级分组（如 连续优化 / 启发式 / 客观赋权 / 深度学习 / 状态估计） |
| `模型类别` | 方法代号或英文名（如 LP / MILP / NSGA-II / TOPSIS / Kalman Filter） |
| `适用场景` | 该方法的典型问题形态，含题号线索 |
| `数据要求` | 输入的形态与规模要求 |
| `原理讲解` | 一句话概括方法原理 |
| `模型输入` / `模型输出` | 输入输出的对象 |
| `关键假设` | 成立前提 |
| `禁忌点` | 直接套用会出错的场景 |
| `模型缺陷` | 固有局限与补救方向 |
| `检验方法` | 独立验证路线 |
| `资料使用声明` | 引用与复核要求 |
| `适用题号` | **检索用经验提示**（字符串数组，非官方题型定义） |

## 五、使用方式

```bash
python scripts/query_dictionary.py --stats                    # 统计
python scripts/query_dictionary.py --list-categories          # 列出大类 / 分组 / 题号信号
python scripts/query_dictionary.py --problem A                # 按题号信号筛选
python scripts/query_dictionary.py --major 优化模型 --group 启发式
python scripts/query_dictionary.py --query 卡尔曼 -v          # 关键词 + 完整档案
python scripts/query_dictionary.py --seq 20 -v                # 按序号
```

## 六、维护约定

- 新增或修订条目时，直接在 `build_dictionary.py` 的 `RECORDS` 中追加 / 修改 `_rec(...)` 调用，然后重新运行脚本；**不要手工编辑 JSON**，否则会与生成器脱节。
- 每条 `_rec` 必须提供 13 个位置参数，缺一即抛错（生成器自带校验）。
- 修订后请同步更新本文件的条目统计表与 `query_dictionary.py --stats` 的输出口径。
- 若官方题型口径发生变化，优先修订「适用题号」的判定规则（`problem_hint`）与本文件的说明，而不是改写模型本身的技术内容。
