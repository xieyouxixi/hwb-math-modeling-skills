# 与其他 Skill 的衔接

## 在完整工作流中的位置

```text
hwb-modeling-workflow（总控）
   └── 终稿闸口（阶段 5）
         ├─ 1. hwb-paper-aigc-auditor          ← 本 Skill（痕迹与建模真实性）
         ├─ 2. hwb-paper-format-checker        （严格格式与匿名性）
         └─ 3. hwb-review-paper                （质量分 + 奖项区间定位）
```

顺序不可颠倒：先修内容真实性，再修格式，最后评审打分。若先评审，分数会因内容问题失真。

## 接口

| 上游 Skill | 传递内容 | 本 Skill 如何使用 |
|---|---|---|
| `hwb-modeling-ideas` | 全文主线与逐问候选模型 | 判断 L3 层“模型是否有主线”，识别模型拼装 |
| `hwb-model-solution-checker` | 红线问题清单 | 与建模真实性分类交叉验证 |
| `hwb-ai-usage-disclosure` | 真实 AI 使用记录 | 用第 6 节核对论文表述与披露是否一致 |

| 下游 Skill | 接收内容 |
|---|---|
| `hwb-ai-usage-disclosure` | 本 Skill 识别出的“需披露的段落“清单 |
| `hwb-review-paper` | 建模真实性分类（用于“模型完备性“评分） |
| `hwb-paper-format-checker` | 无直接接口（格式独立） |

## 与 format-checker 的边界

| 本 Skill 负责 | format-checker 负责 |
|---|---|
| 句式的机器腔 | 标点与字号 |
| 模型是否被真正使用 | 图表编号是否连续 |
| 结果是否与代码一致 | 摘要是否超过两页 |
| 创新点是否有基线 | 匿名性是否合规 |

两者**不得重复计分**。

## 与 review-paper 的协同

`hwb-review-paper` 在做“模型完备性“与“创新点“评分时，应导入本 Skill 的**模型真实性分类**：

| 分类 | 对评分的影响 |
|---|---|
| 真实建模 | 按细则正常给分 |
| 模板化建模 | 模型项按上限的 60%—75% 给分 |
| 模型拼装 | 模型项按上限的 50% 给分，并提示“未形成主线" |
| 伪改进 | 创新点项计 0，并提示补做基线 |
| 结论倒推 | 触发红线，格式与内容项均需人工复核 |

## 使用建议

- **终稿前必跑一次**；
- 写作过程中可只跑 L1（表层）做快速体检，L3 留到模型章节定稿后；
- 若团队确实未使用 AI 辅助，L1/L2 仍值得跑——**模板化建模**与**伪改进**与是否使用 AI 无关。
