# 建模模板化与模型拼装识别

本文件处理 L3 层中最容易被忽略的部分：**模型层面的痕迹**。语言可能是自己写的，但模型结构仍可能高度模板化。

## 一、模型拼装的四种形态

### 形态 1：并列无融合

```text
问1：用模型 A
问2：用模型 B
问3：用模型 C
（A、B、C 之间无数据流、无参数传递、无逻辑衔接）
```

**判据**：把全文的模型名替换成任意其他模型名，论文依然成立 → 拼装。

**改法**：确定一条主线（通常 1—2 个模型），让其余模型成为主线上的环节（数据准备、参数标定、结果校验），并显式写出传递内容。

### 形态 2：引入未用

**判据**：问题分析中引入了 5 个模型，正文只用 2 个。

**改法**：删除未使用的；或把它们改写成“备选方案与其被淘汰的原因”。

### 形态 3：模型与任务错配

**判据**：题目要“给出方案”，论文只给“预测值”；题目要“评价”，论文只给“聚类结果”。

**改法**：补上从模型输出到题目要求交付物的转换步骤。

### 形态 4：方法名堆砌

**判据**：出现“基于 A 与 B 融合的 C 优化模型“这类复合命名，但文中没有明确的融合准则。

**改法**：写清融合准则（误差最小？稳健性优先？），或改回单模型表述。

## 二、参数痕迹

| 痕迹 | 判据 | 改法 |
|---|---|---|
| 参数无源 | 参数凭空出现 | 说明来源：数据估计 / 文献取值 / 网格搜索 |
| 参数过于整齐 | 全部为 0.5、0.8、1.0 这类整数/半整数 | 若为搜索所得，给出搜索范围与最优值 |
| 参数与数据规模不符 | 样本 100 却设 10 个超参数 | 说明调参策略或简化模型 |
| 参数未做灵敏度 | 关键参数固定不动 | 补灵敏度分析 |

## 三、结果痕迹

| 痕迹 | 判据 | 风险 |
|---|---|---|
| 精度异常高 | 测试集 R² > 0.99 且无说明 | 可能过拟合或数据泄露 |
| 误差缺失 | 全文无误差讨论 | 不完整 |
| 结果与代码不符 | 正文数值无法由代码复现 | 严重 |
| 结果无单位 | 数值无单位或量纲 | 不严谨 |
| 只给最优值 | 无区间、无不确定性 | 不完整 |
| 图表与正文不符 | 图中数值与正文不一致 | 严重 |

## 四、创新点痕迹

| 痕迹 | 判据 | 改法 |
|---|---|---|
| 无基线 | 声称“改进“但无对比 | 复现基线并量化提升与代价 |
| 无代价 | 只讲提升不讲成本 | 补充计算量/复杂度/数据需求的代价 |
| 换名不换实 | 把已知方法改了名字叫创新 | 如实表述为“采用”，或说明真正的改动点 |
| 堆模块 | 把多个模块简单串联称为创新 | 说明模块间的必要性（消融实验） |
| 拔高表述 | "首次提出""填补空白" | 删除未经证实的优先权主张 |

## 五、模型真实性分类的判定流程

```text
有主线吗？
├─ 无 → 模型拼装
└─ 有
    ├─ 参数有来源吗？
    │   ├─ 无 → 模板化建模（偏拼装）
    │   └─ 有
    │       ├─ 有独立验证吗？
    │       │   ├─ 无 → 模板化建模
    │       │   └─ 有
    │       │       ├─ 结果与代码一致吗？
    │       │       │   ├─ 否 → 结论倒推
    │       │       │   └─ 是 → 真实建模
    │       └─ （若声称改进）
    │           ├─ 有基线对比吗？
    │           │   ├─ 无 → 伪改进
    │           │   └─ 有 → 真实建模
```

## 六、与“是否使用 AI"的关系

**重要**：模型拼装、伪改进、结论倒推这些问题**与是否使用 AI 无关**。即使全篇手写，也可能出现这些问题。因此：

- 不得因为“团队没用 AI"就跳过 L3 审计；
- 也不得因为 L3 有问题就断定“是用 AI 生成的“——只能说**建模实质薄弱**。
