# 附录、代码与支撑材料规则

## 一、研赛对支撑材料的官方要求

| 项 | 要求 |
|---|---|
| 是否必需 | **可选项**（"此环节不是必须项"） |
| 上传时机 | 论文上传完成后的独立时段（如第二十一届为 9 月 27 日 8:00—9 月 28 日 24:00） |
| 命名 | 压缩包命名 `试题编号+队伍编号`，如 `A24000010001.rar` |
| 大小 | **不超过 50 MB** |
| 论文中注明 | 若上传附件，**须在论文中注明** |
| 内容 | 程序、计算结果等 |
| 其他 | 论文本身"必须上传 pdf 文档，无需上传其他附件" |

> 注：不同届次的具体时段与邮箱请以当年《竞赛通知》为准。

## 二、附录应包含什么

| 内容 | 是否建议 |
|---|---|
| 核心公式的完整推导 | 建议（正文放结论，附录放推导） |
| 数据预处理细节（清洗规则、异常判据） | 建议 |
| 完整代码清单 | 视篇幅；若代码长，放附件并在附录给文件清单 |
| 补充实验结果（正文放主结果） | 建议 |
| 术语与符号补充 | 视需要 |
| 原始数据表 | 一般不必（题目已给） |

## 三、附录的常见问题

| 问题 | 表现 | 影响 |
|---|---|---|
| 空壳附录 | 只写"代码见附件"却不给任何信息 | 显得敷衍 |
| 与正文重复 | 把正文整段搬进附录 | 篇幅浪费 |
| 无编号引用 | 正文说"见附录 A"但附录无 A 标号 | 索引断裂 |
| 代码不可运行 | 缺依赖、缺入口、硬编码路径 | 复现失败 |
| 含身份信息 | 代码注释里有作者姓名/单位/邮箱 | **一票否决** |
| 含环境路径 | 出现 `C:\Users\xxx\...` 这类含用户名的路径 | 泄露身份风险 |
| 修订痕迹残留 | 批注、修订标记、临时文件 | 文件卫生 |
| 超出 50MB | 附件过大导致上传失败 | 提交风险 |

## 四、代码质量清单

| 项 | 要求 |
|---|---|
| 入口明确 | 有 `main` 或 README 说明运行顺序 |
| 依赖声明 | 列出必要的库及其版本 |
| 数据路径 | 相对路径或可配置，不含个人目录 |
| 随机种子 | 固定，或说明多次运行策略 |
| 注释 | 关键步骤有注释，说明"做什么"而非"怎么敲键盘" |
| 模块划分 | 按功能拆分，避免单文件千行 |
| 可复现 | 按 README 步骤能跑出论文中的主要结果 |

## 五、文件卫生检查

| 检查项 | 处理 |
|---|---|
| Word 临时文件（`~$*.docx`） | 删除 |
| 批注与修订 | 接受/拒绝后清除 |
| 隐藏的自定义属性（作者、单位） | 清除文档属性 |
| 转换中间文件 | 删除 |
| 重复版本（v1/v2/final/final2） | 只保留一个主版本 |
| 图片原始文件 | 整理到统一目录 |

> **文档属性是最容易泄露身份的地方**：Word/PDF 的作者、公司、创建者字段常残留真实姓名。提交前务必检查并清空。

## 六、风险分级

| 等级 | 判据 |
|---|---|
| **P0** | 附录或代码中出现培养单位/姓名/队伍编号（身份泄露）；附件超 50MB 或命名不合规（提交失败） |
| **P1** | 引用他人程序未注明来源（抄袭认定风险）；代码不可运行（复现失败） |
| **P2** | 附录空壳、正文与附录引用编号断裂、文档属性残留 |
| **P3** | 格式统一性、注释质量、目录整理 |
