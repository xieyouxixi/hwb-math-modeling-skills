# 模型建立与求解检查规则

## 一、模型建立的四条硬标准

| # | 标准 | 不合格表现 |
|---|---|---|
| 1 | **推导可追溯** | 公式突然出现，无来源、无推导、无引用 |
| 2 | **符号自洽** | 公式中的符号未在符号表定义，或与符号表含义冲突 |
| 3 | **假设被引用** | 用了某条简化却没说是哪条假设允许的 |
| 4 | **约束完整** | 物理/工程约束漏写（研赛最典型失分点） |

### 推导可追溯的检查方法

对每个核心公式追问三句：

1. 这个式子从哪来？（机理推导 / 文献引用 / 数据拟合 / 定义）
2. 中间步骤在哪？（若跳过推导，是否说明了理由）
3. 它的适用条件是什么？（超出条件会怎样）

三句中有两句答不上来，即判定为"公式悬空"，按重要问题报出。

## 二、模型求解的检查要点

| 检查项 | 合格 | 不合格 |
|---|---|---|
| 算法选择 | 说明为何用该算法（规模、结构、精度要求） | "使用 Python 求解" |
| 求解规模 | 给出决策变量数、约束数或状态空间大小 | 完全不提规模 |
| 参数确定 | 说明来源（数据估计 / 文献取值 / 网格搜索） | 参数凭空出现 |
| 收敛性 | 给出收敛判据与迭代次数 | 只给最终结果 |
| 数值稳定性 | 说明初值选取、病态处理 | 完全不提 |
| 最优性 | 给出 gap、下界或与基线对比 | 声称"最优"却无依据 |

## 三、结果与回答的检查要点

**核心判据：题目问什么，论文就答什么。**

| 题目要求的形态 | 论文应给出 |
|---|---|
| 数值 | 数值 + 单位 + 精度 + 条件 |
| 方案/策略 | 可执行方案表（谁在何时做什么） |
| 排序/评级 | 完整排序表 + 依据 |
| 判别结果 | 逐样本结论 + 准确率 |
| 曲线/图像 | 图 + 读图结论 |
| 讨论 | 结论 + 支持证据 + 边界条件 |

**研赛高频失分**：只给数字不给方案；只给方案不说怎么执行；逐问回答有遗漏（如题目问了 4 小问，论文只答 3 个）。

## 四、可复现性清单

| 项 | 要求 |
|---|---|
| 数据版本 | 说明使用了哪份附件、哪几个字段 |
| 预处理 | 清洗规则可复述（阈值、插值方法、异常判据） |
| 随机性 | 固定随机种子；若用多次运行，报告均值与标准差 |
| 超参数 | 给搜索范围与最终取值 |
| 环境 | 语言与主要库版本 |
| 代码 | 若上传附件（≤50MB，须在论文中注明），代码应可运行、有注释、有入口 |

## 五、红线问题

| 红线 | 判据 | 后果 |
|---|---|---|
| 结果违背常识 | 出现负的质量、超过 100% 的概率、发散的预测 | 直接判定模型或数据处理有错 |
| 量纲不自洽 | 等式两侧量纲不一致 | 同上 |
| 倒推痕迹 | 先写结论再补模型；结果异常"完美" | 被视为不可信 |
| 数据不一致 | 正文引用的数据与附件不符 | 可信度崩塌 |
| 复制粘贴未改 | 出现其他题目的残留符号/场景名 | 被视为拼凑 |
| 代码与结果不匹配 | 附件代码跑不出论文中的结果 | 复现失败 |

红线问题一律按 `严重问题` 报出，并给出定位证据。
