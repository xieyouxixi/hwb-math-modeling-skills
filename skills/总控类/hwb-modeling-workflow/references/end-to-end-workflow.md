# 研赛四天全程工作流

本文是 `hwb-modeling-workflow` 的必读参考。它把"华为杯"中国研究生数学建模竞赛的**四天赛程**映射为可执行的阶段，说明每个阶段该调用哪个 Skill、产出什么、以及最容易在哪里翻车。

## 赛程骨架（以 2026 年第二十三届为例）

| 时点 | 事件 | 团队应做的事 |
|---|---|---|
| 赛前 | 报名（6/1–9/19）、审核（–9/20）、缴费（–9/21） | 完成缴费，确认队伍编号生成；准备本地环境与代码脚手架 |
| D-1 09-22 08:00 | 下载加密试题 ZIP 包 + MD5 校验工具 | 校验 ZIP 完整性；**不要**尝试解密（密码次日才公布） |
| D1 09-23 08:00 | 查看解压密码、解密试题、开始答题 | 6 题全读，**2 小时内完成选题** |
| D1 下午 | 题意翻译 + 建模主线 | 调用 `hwb-problem-translator`、`hwb-modeling-ideas` |
| D2 | 模型选型、数据清洗、核心求解 | 调用 `hwb-model-dictionary`，随后进入编码求解 |
| D3 | 结果分析、灵敏度与误差分析、图表定稿 | 边写边跑章节自查 |
| D3 晚 | 论文初稿成形 | 摘要、问题重述、问题分析、模型假设、符号说明齐备 |
| D4 上午 | 终稿打磨 | AIGC 审计 + 严格格式检查 + 综合评审 |
| D4 12:00 前 | 提交 PDF 的 **MD5 识别码** | **一经提交，论文禁止再改** |
| D4 14:00 – D5 24:00 | 上传 PDF 论文 | 命名 `试题编号+队伍编号`，确认点击【提交】 |
| D5 → D6 | 上传附件（可选，≤50MB） | 压缩包命名同上；论文中须注明已上传附件 |

> 竞赛时段为**四天**（约 100 小时），比本科国赛的三天更宽裕，但研赛的**模型完整度与结果严谨度要求明显更高**——多出来的一天通常应该花在灵敏度分析、误差分析和结果检验上，而不是多加模型。

## Stage 1 — 选题（最容易翻车的一步）

研赛 A~F 六题覆盖的领域跨度极大。经验上可按题型族粗分：

| 题型族 | 典型题号倾向 | 常见陷阱 |
|---|---|---|
| 信号与通信建模 | A、B、E | 把物理机理写成了公式堆砌，缺少对噪声/干扰模型的独立验证 |
| 芯片、调度与运筹优化 | A、B、C、D | 约束漏写、可行解不可复现、只给一组解不做敏感性 |
| 数据驱动与预测 | B、C、E、F | 只堆模型不解释机理，训练/验证划分不严谨 |
| 医学与生物 | C、D、E | 缺少对结果临床/生物合理性的讨论 |
| 能源、双碳与地理 | D、F | 指标体系权重无依据，评价类题不给对比基准 |
| 评价与美学量化 | C、F | 主观指标无法量化，问卷/专家打分无信效度检验 |

**选题判据（按优先级）**：

1. 队伍是否有**数据与代码可落地**的把握（不是"感兴趣"）；
2. 题目是否留有**可差异化**的空间（人人都会做的路径拿不到一等奖）；
3. 三人是否都能在同一模型体系上分工（避免一人独撑）。

## Stage 2 — 题意翻译与主线

- `hwb-problem-translator`：逐句拆解，输出**定义表、约束表、数据口径表、交付要求表、跨问题依赖图**。研赛题目常有"补充说明"文件，必须与主赛题合并翻译，否则极易漏掉口径变更。
- `hwb-modeling-ideas`：给出**贯穿全文的主线**（一条主线贯穿 3–5 问，比每问各换一套模型更容易拿高分），并为每问列出候选模型与选型理由。

判据：若翻译报告里出现"该处表述不清"却没有列出**待向命题方提问**的清单，说明拆解不充分。

## Stage 3 — 模型选型

对每个候选模型走一遍 `hwb-model-dictionary`，强制回答：

- 这个模型**服务于哪一问的哪一个具体任务**？
- 输入数据的**样本量、量纲、缺失与异常**是否满足它；
- 关键假设在本题是否成立，若不成立需要什么补救；
- 结果如何**独立验证**（不是用同一模型自证）；
- 失效条件是什么，替代模型是什么。

研赛常见扣分：模型清单很长但**没有一个模型被真正用到底**。宁可两个模型做深，不要六个模型做浅。

## Stage 4 — 写作与章节自查

建议顺序（自查 Skill 与章节一一对应）：

1. `hwb-abstract-checker` — 摘要最后写但最先被读；≤2 页，必须含建模思路/主要方法/模型/结果与结论/创新点；
2. `hwb-problem-restatement` — 只讲"题目要什么"，不得越界写模型；
3. `hwb-problem-analysis-checker` — 讲清"为什么这么建"；
4. `hwb-model-assumption-checker` — 假设必须在本文章节中被真正用到；
5. `hwb-symbol-notation-checker` — 符号表与正文一致，量纲齐全；
6. `hwb-model-solution-checker` — 建立、求解、结果、检验、灵敏度、可复现；
7. `hwb-reference-appendix-checker` — 引用与附录；
8. `hwb-ai-usage-disclosure` — **研赛明确允许使用 AI 作为辅助工具，但引用 AI 产品必须注明来源**；如实披露比隐瞒安全。

## Stage 5 — 终稿闸口

三条独立检查，**顺序不可颠倒**：

1. `hwb-paper-aigc-auditor`：查语言模板化、算法堆砌、建模逻辑断层与"伪改进"；
2. `hwb-paper-format-checker`（严格）：查页面结构、匿名性、篇幅、图表公式编号与文件卫生；
3. `hwb-review-paper`（导入第 2 步报告）：出质量分、奖项区间定位与"数模之星"冲刺潜力。

**最后的清点清单**（逐条打勾再提交）：

- [ ] PDF 命名 = `试题编号 + 队伍编号`
- [ ] 首页封皮保留，**4 个图标未被替换**
- [ ] 除首页外**无任何**培养单位/姓名/队伍编号
- [ ] 摘要 ≤2 页，含建模思路、主要方法、模型、结果与结论、创新点
- [ ] 参考文献格式统一，正文引用与文献表一一对应
- [ ] 引用的 AI 产品已注明来源
- [ ] 附件（若有）≤50MB，命名合规，且在论文中注明
- [ ] 全篇无"待补充""此处略"等遗留占位

## 赛后复盘（研赛真正的复利所在）

研赛的真题与优秀论文是可长期复用的资产。建议赛后：

1. 用 `hwb-review-paper` 对自己的论文重跑一次综合评审，记录实际得分与预测值的偏差，形成个人标定记录；
2. 把本队模型、代码与图表模板归档；
3. 对照本地收录的**历年优秀论文**（见 `数模资料/优秀论文索引/优秀论文索引.csv`，共 229 篇）找出与同题优秀论文的差距维度。
